# 月次の家計レビュー

毎月決まった日に明細を集め、**事実を1枚にまとめて、次の月に何を変えるかを1〜2個決める**ための Skill。
家計簿を毎日つけるのではなく、月1回まとめて振り返る運用を前提にする。

## 守ること

家計の数字は、間違うと判断を誤らせる。以下はどの場面でも守る。

1. **現在日時を最初に取得する。** 締め日・引落日・給料日はすべて日付で決まる。推測しない
2. **数字を推測・改変しない。** 読み取れない金額、ぼやけた画像、途中で切れた明細は「データなし」として確認する
3. **高額・正体不明の支出は推測せず聞く。** 「○/○ 12,800円 カード名のみ」のようなものは、何の支払いかを確認してから分類する
4. **責めない・過度に励まさない。** 超過は事実として書き、理由はユーザーに聞く。トーンは淡々と
5. **認証情報を扱わない。** カード会社・銀行のサイトへのログイン、ID・パスワードの入力はしない。明細はユーザーに用意してもらう
6. **金融商品を勧めない。** 借り換え・繰上返済・投資の判断材料(金利差、回収期間など)は計算して示すが、最終判断はユーザーに任せる。Claude は金融アドバイザーではないと必要に応じて伝える

## 流れ

### 1. プロフィールを確認する
`household-profile.md`(なければ `assets/household-profile-template.md` で最初に聞き取る)を読む。
- カードごとの締め日・引落日、銀行口座、ローン、固定費の一覧、予算、摘要の対応表

### 2. 明細を集める
集める日の決め方と、資料の種類ごとの注意は `references/statement-collection.md` を読む。
集まった資料と足りない資料を一覧にして、足りないものだけを依頼する。

### 3. 明細を読み、分類する
- カード明細は1行ずつ、日付・店名・金額・カードを読み取る
- 銀行CSVは摘要から取引の種類を判定する。読み方は `references/bank-csv.md`
- **カード引落とカード明細を二重に数えない。** 銀行の「カード会社への引落」は、明細側で中身を数えたら支出から除く
- **ローン返済の元本は支出に入れない。** 残高の減少として別に扱う(利息は支出)
- 分類はプロフィールのカテゴリに従う。迷うものは「要確認」に入れて最後に聞く

### 4. レビューをまとめる
出力の形は `references/review-output.md` に従う。中心は次の4つ。
- 収入・支出・差額
- カテゴリ別の支出と予算との差(大きい順)
- 単発の高額支出(一定額以上を一覧にする)
- ローンがある場合は、残高の推移と進捗指標(`references/debt-progress.md`)

### 5. 次の月に変えることを決める
提案は**1〜2個まで**に絞る。たくさん挙げると何も変わらない。
- 効果の大きい順に: 固定費(1回の手続きで毎月効く)→ 頻度の高い少額支出 → 単発の大きな支出
- 金額で示す。「月○円の改善」「○ヶ月で回収」
- 固定費の見直し方は `references/fixed-costs.md`

### 6. 記録する
今月の結果を `review-log.md`(または同等のファイル)に追記する。翌月は前月との比較から始める。
ユーザーが決めたこと(「英会話を週1に変える」など)は、日付と一緒に記録する。
