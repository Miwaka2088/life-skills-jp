# 銀行CSVの読み方

## 基本

銀行の入出金CSVは、日付・摘要・出金・入金・残高の列でできていることが多い。
文字コードが Shift_JIS のことがあるので、読めなければ変換してから読む。

金額の集計はコードで行う(目で足し算しない)。

## 摘要から取引の種類を判定する

摘要には取引先の正式名ではなく、**決済代行会社や収納代行の名前**が出ることが多い。
そのままでは何の取引かわからないので、ユーザーごとに**摘要の対応表**を作ってプロフィールに保存する。

| 摘要の例 | 判定 | 扱い |
|---|---|---|
| 給与・賞与 | 収入 | 収入 |
| カード会社名 | カードの引落 | 支出から除く(中身はカード明細で数える) |
| 収納代行・決済代行会社名 | ローン返済・公共料金など | 対応表で判定。わからなければ確認 |
| カナの個人名・自分の名前 | 振込・自分の口座間の振替 | 対応表で判定。わからなければ確認 |
| ATM | 現金の引き出し | 現金支出として扱う(内訳は不明として残す) |

### 対応表の作り方

1. 初回は、摘要ごとに金額と日付を一覧にして、ユーザーに「これは何か」を聞く
2. 答えをプロフィールの対応表に記録する
3. 2回目以降は対応表で自動判定し、**表にない摘要だけ**を聞く

対応表の例(プロフィールに書く形):

```
| 摘要に出る文字列 | 意味 | 区分 |
|---|---|---|
| ○○保証 出金 | 住宅ローンの返済 | 返済 |
| ○○クレジット 出金 | 自動車ローンの返済 | 返済 |
| ○○ファイナンス 出金 | 家電の分割払い | 返済 |
```

## ローン返済の扱い

- ローンの返済は、元本の部分と利息の部分に分けて考える。元本はローン残高の減少として別に記録し、
  利息の部分は資料で読めれば支出(利息)として記録する
- 進捗は個々の取引ではなく、**月末時点の残高**で見る(`debt-progress.md`)

## よくある取り違え

- カード引落とカード明細の二重計上
- 自分の口座間の振替を支出として数える
- 前月分の引落を今月の支出として数える(カードは「利用月」と「引落月」がずれる)

レビューでは**利用月**で数えるのを基本にし、どちらで数えたかを明記する。
