# ラベルの設計

## 原則

- **ラベルは「後で探すときの棚」。** 届いた瞬間に読むかどうかではなく、後でどこを探すかで分ける
- **階層は2段まで。** 深くすると、どこに入れたか自分でもわからなくなる
- **1通に付けるラベルは基本1つ。** 迷うものは、より後で探しそうな方に入れる

## 構成の例

```
お金/
  カード
  銀行
  ローン
  税金・公的
買い物/
  通販
  フリマ・オークション
  サブスク
住まい/
  電気・ガス・水道
  通信
  管理会社
仕事/
  (勤務先のドメインごとなど)
趣味/
  (趣味ごと)
旅行・予約
ニュースレター
```

ユーザーの生活に合わせて作る。上の例をそのまま使わない。

## 見直しの手順

1. 全ラベルを件数と最終受信日つきで一覧にする
2. 次の4つに分ける

| 区分 | 判定 | 処理 |
|---|---|---|
| 統合 | 同じ意味のラベルが複数ある | 片方に寄せ、空になった方を削除 |
| 階層化 | 同じ分野のラベルが横に並んでいる | 親ラベルの下に移す |
| 削除候補 | 0件、または半年以上新しいメールがない | ユーザーに確認して削除(メールは残る) |
| 維持 | 上のどれにも当たらない | そのまま |

3. 一覧をユーザーに見せ、承認されたものだけ実行する

ラベルを削除しても、メール自体は消えない。ラベルが外れて「すべてのメール」に残る。
このことをユーザーに伝えてから実行する。

## 使っていないサービスの扱い

半年以上使っていないサービスのメールは、ラベルを付けず受信トレイに残す。
- 受信トレイに来ると目に入るので、退会・解約・配信停止の判断がしやすい
- ラベルで隠すと、使っていないサービスに課金が続いていても気づけない

今も使っているかどうかはユーザーに確認する(最終受信日だけで判断しない)。
